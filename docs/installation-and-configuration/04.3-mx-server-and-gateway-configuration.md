This document outlines the deployment, licensing, and initial network configuration for the Imperva Database Activity Monitoring (DAM) SecureSphere Virtual Appliance. 

> **Critical Infrastructure Note:** The SecureSphere Virtual Machine (VM) can strictly only be deployed on an ESX environment that is actively managed by VMware vCenter. Deployments on standalone ESXi hosts or other hypervisors require contacting Imperva support for assistance.

---

## 1. Virtual Appliance Deployment (vSphere)

Before initializing the SecureSphere software, the virtual appliance must be provisioned within your VMware environment.

### 1.1 OVF Template Import
1. Launch and log into the **VMware vSphere client**.
2. Navigate to the top menu and select **File > Deploy OVF Template** to launch the Import Virtual Appliance wizard.
3. In the wizard, click **Browse**, locate your downloaded SecureSphere installation file, and select it. Click **Next**.
4. Verify the OVF template details presented on the screen and click **Next**.
5. Review the End User License Agreement (EULA), select **Accept**, and proceed by clicking **Next**.

### 1.2 VM Configuration
1. **Naming:** Provide a clear, identifiable name for this specific SecureSphere instance and click **Next**.
2. **Deployment Type:** Select your required Deployment Configuration. *Note: The hardware and resource details for each configuration type are displayed dynamically as you select them.* Click **Next**.
3. **Storage:** Select the appropriate datastore for provisioning the virtual machine files and click **Next**.
4. **Networking:** Accept the default Network Mapping settings for now. You will configure specific Virtual NICs later according to your network topology. Click **Next**.
5. **Finalization:** Review the final configuration summary and click **Finish** to deploy the VM.

---

## 2. Initial Licensing and GUI Setup

Once the VM is deployed and powered on, you must apply your enterprise license before configuring the command-line interfaces. 

### 2.1 Accessing the Web Interface
1. Open a web browser and navigate to the MX Server's IP address using HTTPS on port `8083` (e.g., `https://<IP address of MX>:8083`).
2. The EULA will be displayed; read it and click **Accept**.
3. You will be immediately prompted to set an **Admin password** specifically for the web GUI. Follow the on-screen instructions to set this.

### 2.2 License Activation
You will need the "Welcome Imperva SecureSphere Customer" email, which contains your Enterprise License Code as well as your username and password for the Imperva FTP site.

1. On the **Upload License** window, click the hyperlink labeled "here" to open the Imperva Activation Portal.
2. The portal will automatically fill in the Challenge string.
3. Enter your **Enterprise License Code** and your **Email Address**.
4. Accept the EULA checkbox, complete the visual/audio verification strings (reCAPTCHA), and click **Activate**.
5. Check your provided email inbox for an attachment containing the license file and save it locally.
6. Return to the SecureSphere Upload License window, click **Browse**, select the saved file, and click **Upload**.

## 3. Global First-Time Login (FTL) Prerequisites

Configuration is performed directly in the virtual appliance console using the `ftl` command. 

### 3.1 SecureSphere Password Policy
All system passwords configured during this process must adhere to the following strict characteristics:
* **Length:** 10 to 14 characters.
* **Complexity:** Must include at least one number, one uppercase letter, and one special character from the following list: `* + = # % ^ : / ~ . , [ ] _`.
* **Repetition:** Cannot contain more than two identical characters in succession.

### 3.2 Setup Guidelines
* **DNS Configuration:** If you choose to configure a DNS client during setup, ensure the specified IP address points to a real, reachable DNS server at the time of configuration.
* **Recommended Settings:** The setup wizard will mark certain yes/no options as "(Recommended)". The system operates more efficiently when these are accepted (by entering `y`).
* **Automation:** It is possible to automate the first-time login process specifically for configuring the gateway in sniffing mode (refer to the Imperva On-Premises Administration Guide for automation details).

## 4. Management Server (MX) / SOM Configuration

> **Note:** If you are installing a SecureSphere Operation Manager (SOM), you will use this exact same MX procedure. 

### Phase 1: Authentication & Initialization
1. Open the virtual appliance console and log in using the default credentials: Username `admin`, Password `admin`.
2. You will be forced to change the admin password immediately (adhering to the password policy above).
3. Run the command `ftl` to launch the configuration tool.
4. Type `1` to configure a Management Server (MX) or `2` for a SOM, and press **Enter**. (Option `3` is reserved for configuring network settings only).

### Phase 2: Network Configuration
1. **Management Interface:** Enter `n` when asked if you want to change the default interface. Input the IP Address in CIDR format (e.g., `192.168.1.1/24`). Decline IPv6 unless required.
2. **LAN Interface:** Enter `y` to configure a LAN interface, decline changing the default interface name, and input the LAN IP Address in CIDR format (e.g., `192.168.5.5/24`). Decline IPv6.
3. **Default Gateway:** Enter `y` (Recommended) to set an IPv4 default gateway and provide the reachable address (e.g., `192.168.1.254`). Decline specifying a device.
4. **DNS:** Enter `y` or `n` to configure a DNS client based on your environment availability.

### Phase 3: System Users & Passwords
You must define secure passwords for three distinct user roles:
| User Account | Purpose / Scope |
| :--- | :--- |
| **Linux `root`** | OS-level access. This password is also applied to the grub bootloader. |
| **SecureSphere `admin`** | Used to log into the management server via `impcfg`. Must be identical across all appliances managed by this MX. |
| **`system` user** | Database Administrator account used occasionally for DB changes and support troubleshooting. |

### Phase 4: Hostname & Environment Variables
1. **Hostname:** Enter a short name or a Fully Qualified Domain Name (FQDN). *If using FQDN: separate parts with periods, start each part with a letter, and ensure each part contains at least two valid characters (letter, digit, underscore, dash)*.
2. **Large Scale MX:** Enter `y` if this MX needs to operate in large scale mode (capable of handling up to 50 Large Scale Gateways).
3. **Time & NTP:** Select your geographic region (or enter `11` for Posix TZ format), select your country, and verify the local time. Enter `y` (Recommended) to configure an NTP client and provide the IPv4 addresses of your NTP servers (separated by spaces).
4. **Apply:** Press **Enter** to finalize. **Do not reboot the appliance.** The MX configuration processing will take approximately 10 minutes.

## 5. Gateway Configuration

> **Prerequisite:** Before configuring a Gateway, its associated Management Server (MX) must be fully up, running, and reachable.

### Phase 1: Authentication & Initialization
1. Open the virtual appliance console and log in using `admin` / `admin`.
2. Change the default password to meet the security policy.
3. Run the command `ftl`.
4. Type `3` to select Gateway configuration and press **Enter**.

### Phase 2: Network & Host Configuration
1. **Network Interfaces:** Follow the exact same procedure as the MX Server to set the Management Port IP/CIDR, LAN Interface IP/CIDR, IPv4 Default Gateway, and DNS client.
2. **System Users:** Define passwords for the following Gateway roles:
   * **Linux `root` / `grub` user**.
   * **SecureSphere `admin` user** (used for `impcfg` login).
   * **`imperva` user** (specifically responsible for communication with remote agents).
3. **Hostname:** Define the host name (short or FQDN) following the same formatting rules as the MX.
4. **MX Link:** Enter the IPv4 Address of the Management Server (MX) this Gateway will report to (e.g., `10.1.1.205`).

### Phase 3: Operational Modes & Finalization
1. **Operation Mode:** Select your preferred gateway operation mode from the numbered list provided in the CLI.
2. **Time & NTP:** Configure the time zone and NTP client exactly as done for the MX server.
3. **Large Scale Gateway (DSF Hub Only):** Enter `y` if you wish to configure the gateway in Sonar Only mode. *Note: This mode routes DB audit data exclusively to the DSF Hub, allowing the gateway to monitor up to three times the standard traffic volume*.
4. **Apply:** Press **Enter** to finalize. **Do not reboot the appliance.** The Gateway configuration processing will take approximately 5 minutes.
